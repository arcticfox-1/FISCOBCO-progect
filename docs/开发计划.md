# 开发计划

> 总学时 100，按实训要求的六阶段拆解为可执行任务。每阶段以**可检查的产出物**作为完成判据。

---

## 阶段一：需求与总体设计（10 学时）

**目标**：把"要做什么"钉死，后续不再反复改。

- [x] 梳理角色：监管、生产、检测、物流、销售、消费者
- [x] 绘制流程图：种植 → 采收 → 检测 → 运输 → 销售
- [ ] 绘制角色用例图（UML，可用 draw.io）
- [x] 确定实体：批次、溯源记录、质检报告、处置记录、链上回执
- [x] 数据库表结构（`sql/schema.sql`）
- [x] 链上数据结构（`contracts/`）
- [x] 接口清单（`docs/系统设计.md` 第五节）

**产出**：`docs/需求分析.md`、`docs/系统设计.md`、`sql/schema.sql`
**完成判据**：角色权限矩阵无遗漏；每个功能点能对应到接口和表字段。

---

## 阶段二：环境搭建与基础工程（10 学时）

**目标**：链通、库通、前后端能跑起来。

- [ ] 用 `build_chain.sh` 搭 4 节点单群组链，`start_all.sh` 启动
- [ ] 校验：4 节点 `connected`，区块高度增长
- [ ] 部署控制台 console，能 `getBlockNumber`
- [ ] 建库 `agri_trace`，执行 `sql/schema.sql`
- [ ] 后端骨架：Spring Boot 启动，连上 MySQL
- [ ] SDK 连通性测试：写一个 `getBlockNumber` 的单元测试
- [ ] 前端骨架：Vite 启动，路由与登录页可访问

**产出**：可运行的链、库、空壳工程
**完成判据**：`mvn test` 中 SDK 连通用例通过；前端 `npm run dev` 打开无报错。

> 此阶段最容易卡住的是**证书**。务必从当前链的 `nodes/127.0.0.1/sdk/` 拷 `ca.crt`、`sdk.crt`、`sdk.key`，三件套配套使用。

---

## 阶段三：智能合约开发与验证（20 学时）

**目标**：把业务规则写死在链上。

- [x] `RoleControl.sol`：主体注册、监管审核、角色授予撤销
- [x] `Traceability.sol`：批次登记、记录追加、状态机、更正、处置
- [ ] 编译通过（console `deploy` 或 `solc`）
- [ ] 部署两个合约，记录地址与交易哈希
- [ ] 合约单测（至少覆盖）：
  - [ ] 重复 batchId 回滚
  - [ ] 越权角色写入回滚
  - [ ] 跳步（未采收检测）回滚
  - [ ] 不合格批次运输/销售回滚
  - [ ] 更正记录 refIndex 正确
  - [ ] 非监管调用 disposeBatch 回滚
- [ ] 事件监听验证：能捕获 `BatchCreated`、`InspectionSubmitted`

**产出**：合约源码、部署脚本、调用记录截图
**完成判据**：6 条单测全部通过；控制台能查到批次数据。

---

## 阶段四：前后端业务实现（30 学时）

**目标**：五环节能完整录一遍，扫码能看全程。

- [ ] 登录与 JWT 拦截器、角色注解
- [ ] 主体审核（监管）与链上 `setEntityStatus` 同步
- [ ] 产品档案 CRUD
- [ ] 批次登记：落库 + 上链 + 回执校验
- [ ] 种植 / 采收 / 运输 / 销售四个录入页
- [ ] 质检提交：文件上传 + SHA-256 + 结论上链
- [ ] 不合格拦截：前端按钮禁用 + 后端校验 + 合约 revert 兜底
- [ ] 溯源页：时间轴展示、报告摘要、交易哈希跳转
- [ ] 二维码生成与批量导出
- [ ] 多维查询（批次 / 主体 / 时间）
- [ ] 上下游追踪
- [ ] 小程序：扫码 → 溯源页 → 报告预览

**产出**：可演示的完整业务流
**完成判据**：`TC-01` 正常链路一次跑通，6 条记录均显示交易哈希。

## 阶段五：集成测试与问题修复（20 学时）

- [ ] 执行 `docs/测试方案.md` 中 TC-01 ~ TC-09
- [ ] 准备 10 个批次数据（含 2 个不合格），每批 ≥4 条记录
- [ ] 记录失败用例并修复，保留修复前后截图
- [ ] 并发测试：20 并发登记，检查回执不错乱
- [ ] 上链失败演练：停节点后提交，确认页面不显示"已存证"

**产出**：测试报告（用例表 + 截图 + 结论）
**完成判据**：9 类用例全部有结果记录，无未修复的阻塞缺陷。

## 里程碑与风险

| 里程碑 | 时间点 | 判定 |
| --- | --- | --- |
| M1 设计定稿 | 阶段一末 | 需求与设计文档评审通过 |
| M2 链通 | 阶段二末 | 4 节点出块，SDK 能读块高 |
| M3 合约可用 | 阶段三末 | 6 条单测通过 |
| M4 主流程通 | 阶段四中 | 单批次五环节走通 |
| M5 可演示 | 阶段五末 | 正常 + 异常两条演示链路都能跑 |

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 证书版本不匹配 | SDK 连不上链 | 三件套从同一条链拷贝，版本对齐 2.9.1 |
| 合约编译版本冲突 | 部署失败 | `pragma` 固定 0.4.25，与 console 一致 |
| 上链超时误判 | 状态与链不一致 | 以回执为准，加轮询重试 3 次，失败标记 `chain_status=2` |
| 文件摘要不一致 | 校验用例失败 | 上传即算摘要，禁止事后替换文件；校验时重算 |
| 进度落后 | 无法按期答辩 | 优先保 M4/M5，图表统计等非核心功能可裁剪 |
