## 二、用例清单

### TC-01 正常流转（核心用例）

| 项 | 内容 |
| --- | --- |
| 前置 | 各主体已审核启用，角色已授予 |
| 步骤 | ① 生产登记批次 AG20260312001<br>② 录入种植记录<br>③ 录入采收记录<br>④ 检测机构提交结论=合格<br>⑤ 物流录入运输交接<br>⑥ 销售上架<br>⑦ 扫码查询 |
| 预期 | 状态依次：0→1→2→3→5→6；共 6 条记录；每条有 `txHash` 且回执 `status=0x0`；溯源页时间正序展示 |
| 判定 | 状态与记录数全部匹配，且区块浏览器/控制台可查到对应交易 |

### TC-02 重复批次

| 项 | 内容 |
| --- | --- |
| 步骤 | 用 AG20260312001 再次提交登记 |
| 预期 | 接口返回失败，提示"批次已存在"；`t_batch` 不新增记录；控制台可见 revert 信息 `batch already exists` |
| 判定 | 数据库唯一索引未冲突报错（说明被业务层先拦截），链上未产生新批次 |

### TC-03 越权写入

| 项 | 内容 |
| --- | --- |
| 步骤 | 用 `seller01` 的 token 调用 `POST /api/trace/planting` |
| 预期 | 接口 403，提示"无权限"；不落库；若绕过接口直连合约，revert `insufficient role` |
| 判定 | 两层拦截都要验证：接口层 + 合约层 |

### TC-04 不合格批次销售

| 项 | 内容 |
| --- | --- |
| 前置 | AG20260312002 已检测为不合格（status=4） |
| 步骤 | 销售账号尝试 `POST /api/trace/sales` |
| 预期 | 接口拒绝；直连合约 revert `unqualified batch cannot be sold`；前端上架按钮置灰 |
| 判定 | 交易未上链，`t_chain_tx` 无成功记录 |

### TC-05 摘要不一致

| 项 | 内容 |
| --- | --- |
| 步骤 | ① 正常提交质检报告，记录 `file_hash`<br>② 手动修改链下报告 PDF（改一个字符）<br>③ 调用 `GET /api/trace/{batchId}/verify` |
| 预期 | 该条记录 `consistent=false`；`verifyDigest` 返回 false；页面标红"校验不通过" |
| 判定 | 其余记录仍为 true，仅被改记录变 false |

### TC-06 上链失败

| 项 | 内容 |
| --- | --- |
| 步骤 | 停止 2 个以上节点（破坏共识）后提交一条种植记录 |
| 预期 | 接口返回失败；`t_chain_tx.status=2` 且记录 `error_msg`；**页面必须显示"上链失败/未存证"，不得显示绿色已存证** |
| 判定 | 恢复节点后可重新提交成功，且不产生重复记录 |

### TC-07 跳步操作

| 项 | 内容 |
| --- | --- |
| 步骤 | 批次仅登记（status=0）时直接提交质检 |
| 预期 | revert `inspection requires harvested status` |
| 判定 | 链上无检测记录 |

### TC-08 未审核主体写入

| 项 | 内容 |
| --- | --- |
| 步骤 | 新注册主体未审核，直接调用登记批次 |
| 预期 | revert `entity not active`；接口提示"主体待审核" |
| 判定 | 审核通过后同一操作可成功 |

### TC-09 更正记录

| 项 | 内容 |
| --- | --- |
| 步骤 | 对种植记录（index=0）追加更正说明 |
| 预期 | 原记录内容不变；新增一条 `stage=6`、`refIndex=0` 的记录；溯源页在原记录下显示"已更正"标注 |
| 判定 | `getRecord` 读原记录仍为旧值，`getCorrectionCount` 增 1 |

### TC-10 并发写入（非功能）

| 项 | 内容 |
| --- | --- |
| 步骤 | 20 个线程并发登记 20 个不同批次 |
| 预期 | 20 条全部成功，`txHash` 互不重复，`blockNumber` 递增 |
| 判定 | 无回执错配，无重复 batchId |

## 四、执行方式

### 4.1 接口级（Postman / curl）

```bash
# 登录取 token
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"producer01","password":"123456"}'

# 登记批次
curl -X POST http://localhost:8080/api/batch \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"batchId":"AG20260312011","productId":1,"origin":"山东省寿光市"}'

# 溯源查询（公开）
curl http://localhost:8080/api/trace/AG20260312001

# 摘要校验
curl http://localhost:8080/api/trace/AG20260312001/verify
```

### 4.2 合约级（console）

```bash
# 直接调用合约验证越权/状态约束
[group:1]> call Traceability <addr> createBatch "AG20260312001" "草莓" "寿光"
# 预期回滚：batch already exists

[group:1]> call Traceability <addr> submitInspection "AG20260312005" "早检" 0x1234 true
# 预期回滚：inspection requires harvested status
```

### 4.3 页面级

按"验收演示脚本"走一遍，逐屏截图，重点截：状态流转、交易哈希、拦截提示、校验结果。
