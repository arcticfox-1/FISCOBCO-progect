## 一、总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                        接入层                                 │
│  Vue 3 管理端（B端）        微信小程序（C端扫码）              │
│  生产/检测/物流/销售/监管    消费者查看溯源履历                 │
└──────────────┬───────────────────────────┬───────────────────┘
               │ HTTPS + JWT               │
┌──────────────▼───────────────────────────▼───────────────────┐
│                   Spring Boot 应用层                          │
│  Controller → Service → ChainService → FISCO BCOS Java SDK    │
│  · JWT 鉴权  · 角色拦截  · 文件摘要  · 二维码  · 回执处理      │
└──────────────┬───────────────────────────┬───────────────────┘
               │ JDBC                      │ Channel RPC
┌──────────────▼──────────────┐  ┌─────────▼────────────────────┐
│  MySQL（链下明细）           │  │  FISCO BCOS 联盟链（4 节点） │
│  批次/记录/报告/回执/日志    │  │  RoleControl + Traceability  │
│  文件存本地或 MinIO          │  │  PBFT 共识，单群组           │
└─────────────────────────────┘  └──────────────────────────────┘
```

**分层职责**

| 层 | 职责 | 不该做的事 |
| --- | --- | --- |
| Controller | 参数校验、鉴权注解、返回统一结构 | 不写业务判断 |
| Service | 业务规则、状态机校验、事务 | 不直接拼合约参数 |
| ChainService | 合约方法封装、私钥签名、回执解析 | 不关心业务语义 |
| 合约 | 唯一性、权限、状态、追加存证 | 不存大文本与文件 |

> 关键设计：**链下先校验，链上再兜底**。业务规则在 Service 判一次给友好提示，合约再判一次防止绕过接口直连链。

## 二、链上数据结构

### 2.1 角色位掩码

| 角色 | 值 | 说明 |
| --- | --- | --- |
| `ROLE_REGULATOR` | 1 | 监管 |
| `ROLE_PRODUCER` | 2 | 生产主体 |
| `ROLE_INSPECTOR` | 4 | 检测机构 |
| `ROLE_LOGISTICS` | 8 | 物流企业 |
| `ROLE_SELLER` | 16 | 销售商 |

一个地址可叠加多个角色（按位或），例如 `2 | 16 = 18` 表示既生产又自销。

### 2.2 批次状态机

```
 ①登记(0) ──种植──► ①种植中(1) ──采收──► ②已采收(2)
                                              │
                                      ┌───────┴────────┐
                                  检测合格          检测不合格
                                      │                │
                                  ③合格(3)         ④不合格(4)
                                      │                │
                                   运输              处置
                                      │                │
                                 ⑤运输中(5)       ⑧已处置(8)
                                      │
                                   上架 ──► ⑥已上架(6) ──► ⑦已售出(7)
```

**非法流转（合约直接 revert）**：未采收→检测、不合格→运输、不合格→销售、检测前→销售。

### 2.3 记录结构

```solidity
struct TraceRecord {
    uint8   stage;      // 1种植 2采收 3检测 4运输 5销售 6更正
    address operator;   // 上链主体地址
    string  summary;    // 环节摘要
    bytes32 dataHash;   // 链下数据/报告 SHA-256
    uint256 timestamp;  // 上链时间
    bool    qualified;  // 检测结论
    uint256 refIndex;   // 更正指向的原记录下标
}
```

**只追加不修改**：没有任何修改/删除接口。录入错误通过 `addCorrection` 追加一条 `stage=6` 的记录，`refIndex` 指向原记录，前端展示时在原记录下方标注「已更正」。

### 2.4 合约接口

| 合约 | 方法 | 调用者 | 说明 |
| --- | --- | --- | --- |
| RoleControl | `registerEntity` | 任何主体 | 自主注册，待审核 |
| RoleControl | `setEntityStatus` | 监管 | 启用/停用 |
| RoleControl | `grantRole` / `revokeRole` | 监管 | 授权/撤权 |
| RoleControl | `hasRole` / `isActive` | 任何人 | 权限查询 |
| Traceability | `createBatch` | 生产 | 批次唯一登记 |
| Traceability | `addTraceRecord` | 生产/物流/销售 | 种植、采收、运输、销售 |
| Traceability | `submitInspection` | 检测 | 质检结论 + 报告摘要 |
| Traceability | `addCorrection` | 原操作人/监管 | 追加更正 |
| Traceability | `disposeBatch` | 监管 | 不合格处置 |
| Traceability | `getBatch` / `getRecord` | 任何人 | 查询 |
| Traceability | `verifyDigest` | 任何人 | 摘要校验 |
| Traceability | `setPaused` | 管理员 | 紧急暂停 |

**合约事件**（后端订阅/审计用）：
`BatchCreated`、`TraceRecordAdded`、`InspectionSubmitted`、`CorrectionAdded`、`BatchStatusChanged`、`BatchDisposed`。

## 三、链上链下职责划分

| 数据 | 存放位置 | 理由 |
| --- | --- | --- |
| 批次号、产品名、产地 | 链上 + 链下 | 链上保证唯一与可信，链下便于检索 |
| 业务发生时间、上链时间 | 双方 | 上链时间取区块时间戳，防篡改 |
| 环节摘要（短文本） | 链上 | 便于直接展示，控制长度 ≤ 200 字 |
| 环节明细 JSON | 仅链下 | 字段多、体积大 |
| 质检报告 PDF | 仅链下 | 文件存储 |
| 报告文件 SHA-256 | 链上 | 完整性凭证 |
| 图片、视频 | 仅链下 | 体积大 |
| 交易哈希、区块号 | 仅链下 | 链上可反查，无需再存 |

> 上链内容一律控制在 1KB 以内，避免区块膨胀。演示规模（10 批次 × 6 记录）单群组 4 节点完全够用。

## 四、数据库设计

完整建表语句见 [`sql/schema.sql`](../sql/schema.sql)。核心表关系：

```
t_entity 1 ──── n t_user
   │ 1
   │ n
t_product 1 ──── n t_batch 1 ──── n t_trace_record 1 ──── 1 t_inspection_report
                      │ 1                    │
                      │ 1                    │ n
                 t_disposal            t_chain_tx（按 tx_hash 关联）
```

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `t_entity` | 参与主体 | `chain_address` 唯一，绑定链上账户 |
| `t_user` | 登录账号 | `role_code` 对应位掩码 |
| `t_product` | 农产品档案 | 纯链下 |
| `t_batch` | 批次主线 | `batch_id` 唯一，`status` 与链上同步 |
| `t_trace_record` | 业务记录 | `tx_hash`、`record_index`、`ref_index` |
| `t_inspection_report` | 质检报告 | `file_hash` 上链 |
| `t_disposal` | 不合格处置 | 一batch一条 |
| `t_chain_tx` | 交易回执 | `status` 是"是否存证成功"的唯一依据 |
| `t_oper_log` | 操作日志 | 审计用 |

**状态同步策略**：以链上为准。交易回执 `status=1` 才更新 `t_batch.status`；回执失败则回滚业务状态，写入 `t_chain_tx.error_msg`。

## 五、接口清单

统一响应：`{ "code": 200, "message": "success", "data": {} }`
鉴权：`Authorization: Bearer <jwt>`，除 `/api/auth/login` 与公开溯源查询外均需登录。

| 方法 | 路径 | 角色 | 说明 |

| GET | `/api/auth/info` | 登录 | 当前用户与主体信息 |

## 六、关键流程时序（批次登记）

```
Vue          Controller        Service         ChainService       链
 │  POST /api/batch │              │                 │            │
 ├─────────────────►│ 校验角色/参数 │                 │            │
 │                  ├─────────────►│ 查重 batch_id    │            │
 │                  │              ├────────────────►│            │
 │                  │              │                 ├─ createBatch ─►│
 │                  │              │                 │◄─ 回执 ─────┤
 │                  │              │ 回执 status=1?  │            │
 │                  │              │  是→落库(chain_status=1)      │
 │                  │              │  否→落库(chain_status=2,失败) │
 │                  │◄─────────────┤                 │            │
 │◄─────────────────┤ 返回结果+txHash              │            │
```

**失败处理铁律**：回执 `status != 1` 时，接口返回业务失败，页面显示「上链失败，未存证」，不得出现绿色"已存证"标识。

## 七、安全设计

| 风险 | 措施 |
| --- | --- |
| 私钥泄露 | 私钥加密存于服务端配置/密钥库，不入库、不进 Git；`.gitignore` 已排除 `*.key` |
| 越权调用 | JWT + 角色注解 + 数据归属校验；合约层 `onlyRole` 二次拦截 |
| 重复提交 | `batch_id` 数据库唯一索引 + 合约 `exists` 双保险；前端按钮防抖 |
| 文件篡改 | 上传即算 SHA-256 存链，查询时重算比对 |
| SQL 注入 | MyBatis-Plus 参数化 |
| 接口刷量 | 登录接口限流，失败 5 次锁定 10 分钟 |
| 审计 | `t_oper_log` 记录关键操作，链上事件可交叉核对 |
