# 需求分析

> 依据：《项目一 基于 FISCO BCOS 联盟链的农产品质量安全溯源系统设计与实现》实训要求
> 版本：v1.0　编写日期：2026-11-03

---

## 一、项目目标

围绕**一种农产品**，以**批次**为主线，打通「种植 → 采收 → 检测 → 运输 → 销售」五个环节，把关键业务记录的质量摘要写入 FISCO BCOS 联盟链，实现：

1. **全程可追溯**：任一批次可还原完整流转履历；
2. **数据可信**：链上记录不可篡改，交易回执可核验；
3. **责任可界定**：每个环节的操作主体、时间、摘要均留痕；
4. **异常可处置**：不合格批次无法进入正常销售，可追查上游来源与下游去向。

**实施边界**（原文要求）：
- 人工录入模拟生产与流通信息，**不接入真实物联网设备**；
- 质检报告**原件存链下**，链上仅存批次、主体、业务时间、状态与文件摘要；
- 不把上链等同于实物质量证明，需在系统与报告中明确该声明。

## 二、参与角色与权限矩阵

| 角色 | 编码 | 可执行操作 | 不可执行 |
| --- | --- | --- | --- |
| 监管人员 | `REGULATOR` | 审核/启停主体、授予角色、查看全量数据、处置不合格批次、发起更正 | 录入生产业务记录 |
| 生产主体 | `PRODUCER` | 登记批次、种植记录、采收记录、对本人记录发起更正 | 检测、运输、销售 |
| 检测机构 | `INSPECTOR` | 提交质检报告与结论（合格/不合格） | 登记批次、运输、销售 |
| 物流企业 | `LOGISTICS` | 运输交接记录（车辆、起止地、时间） | 检测、销售 |
| 销售商 | `SELLER` | 上架登记、销售记录 | 检测、运输 |
| 消费者 | 匿名 | 扫码查看溯源履历与报告摘要 | 任何写操作 |

**权限实现原则**：链上以地址位掩码做**入口校验**，链下以角色 + 数据归属做**接口校验**，两层都要有，缺一不可（越权测试用例同时验证两层）。

## 三、业务流程

```
生产主体            检测机构           物流企业          销售商          监管
   │                   │                  │                │              │
   ├─① 登记批次─────────┼──────────────────┼────────────────┼──────────────┤
   │   batchId 唯一     │                  │                │              │
   ├─② 种植记录         │                  │                │              │
   ├─③ 采收记录         │                  │                │              │
   │                   ├─④ 提交质检───────┼────────────────┼──────────────┤
   │                   │  合格 → 放行      │                │              │
   │                   │  不合格 → 拦截    │                │   ⑤ 处置 ◄───┤
   ├───────────────────┼──────────────────┼─⑥ 运输交接─────┤              │
   │                   │                  │                ├─⑦ 上架销售───┤
   │                   │                  │                │              │
   └───────────────────┴──────────────────┴────────────────┴──⑧ 扫码溯源───┘
```

**关键约束（必须在合约中强制执行）**

| 编号 | 约束 | 违反时行为 |
| --- | --- | --- |
| C-01 | 同一 `batchId` 不可重复登记 | 交易 revert：`batch already exists` |
| C-02 | 未审核启用的主体不可写入 | revert：`entity not active` |
| C-03 | 角色与环节不匹配不可写入 | revert：`insufficient role` |
| C-04 | 状态未到不可跳步（如未采收不能检测） | revert：`requires harvested status` |
| C-05 | 检测不合格的批次不可运输、不可销售 | revert：`unqualified batch cannot be sold` |
| C-06 | 历史记录不可修改，只能用更正记录追加 | 无修改接口，仅 `addCorrection` |
| C-07 | 上链失败不得标记为已存证 | 以交易回执 `status` 为准，失败落 `t_chain_tx.status=2` |

## 四、功能需求清单

### 4.1 基础支撑

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-01 | 用户登录 | 账号密码登录，返回 JWT；按角色返回可见菜单 |
| FR-02 | 主体注册与审核 | 主体提交资料 → 监管审核启用 → 分配链上地址与角色 |
| FR-03 | 角色授权 | 监管方可授予/撤销角色，合约同步 `grantRole` / `revokeRole` |
| FR-04 | 链上账户管理 | 为每个主体生成/托管密钥，地址与 `t_entity.chain_address` 绑定 |

### 4.2 业务功能

| 编号 | 功能 | 操作角色 | 上链内容 |
| --- | --- | --- | --- |
| FR-05 | 农产品档案管理 | 生产主体 | 不上链（纯链下） |
| FR-06 | 批次登记 | 生产主体 | batchId、产品、产地、时间 |
| FR-07 | 种植记录 | 生产主体 | 摘要、附件摘要、时间 |
| FR-08 | 采收记录 | 生产主体 | 采收量、时间、摘要 |
| FR-09 | 质检提交 | 检测机构 | 报告编号、结论、报告文件摘要 |
| FR-10 | 运输交接 | 物流企业 | 车辆、起止地、交接时间 |
| FR-11 | 销售登记 | 销售商 | 门店、上架时间、销量 |
| FR-12 | 录入更正 | 原操作人/监管 | 更正说明 + 新摘要，指向原记录 |
| FR-13 | 不合格处置 | 监管 | 处置方式、处置时间 |

### 4.3 溯源与追踪

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-14 | 溯源码生成 | 每批次生成含 `batchId` 的二维码，支持批量导出 |
| FR-15 | 扫码溯源 | 扫码后按时间正序展示五环节履历、报告摘要、交易凭证 |
| FR-16 | 摘要校验 | 用链下文件重算 SHA-256，与链上比对，输出"一致/不一致"结论 |
| FR-17 | 多维查询 | 按批次号、主体、时间区间组合查询 |
| FR-18 | 上游追溯 | 由异常批次追查生产主体、地块、投入品记录 |
| FR-19 | 下游追踪 | 由异常批次追查运输单号、销售门店、已售数量 |

## 五、测试矩阵（验收必测）

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-01 | 正常流转 | 登记→种植→采收→检测合格→运输→销售 | 状态依次推进，6 条记录全部上链成功 |
| TC-02 | 重复批次 | 用已存在的 `batchId` 再次登记 | 交易 revert，提示"批次已存在"，库中不新增 |
| TC-03 | 越权写入 | 用销售商账号提交种植记录 | 合约 revert `insufficient role`，接口返回 403 |
| TC-04 | 不合格批次销售 | 检测不合格后尝试上架 | 合约 revert `unqualified batch cannot be sold` |
| TC-05 | 摘要不一致 | 篡改链下报告文件后校验 | `verifyDigest` 返回 false，页面标红"校验不通过" |
| TC-06 | 上链失败 | 停掉节点或改错合约地址后提交 | 接口返回失败，`chain_status=2`，**页面不得显示"已存证"** |
| TC-07 | 跳步操作 | 未采收直接提交检测 | revert `requires harvested status` |
| TC-08 | 未审核主体写入 | 主体未启用即登记批次 | revert `entity not active` |
| TC-09 | 更正记录 | 对种植记录追加更正 | 原记录不变，新增更正记录且 `refIndex` 正确 |

## 六、数据准备要求

| 项 | 要求 | 落地方式 |
| --- | --- | --- |
| 农产品 | 1 种（建议草莓或柑橘，季节性强、环节清晰） | `t_product` 1 条 |
| 批次 | **≥ 10 个** | `scripts/init_data` 批量生成 |
| 异常批次 | **其中 2 个**检测不合格 | 检测结论置 false，走处置流程 |
| 环节记录 | 每批次 **≥ 4 条** | 种植、采收、检测、运输（销售视批次而定） |
| 模拟材料 | 质检报告 PDF、农产品图片 | `deploy/mock/` 存放 |
| 测试账号 | 5 类角色各至少 1 个 | `sql/init_data.sql` |

## 七、非功能需求

| 项 | 指标 |
| --- | --- |
| 上链响应 | 单笔交易确认 ≤ 3s（4 节点 PBFT，本地环境） |
| 溯源查询 | 单批次全链路查询 ≤ 1s |
| 并发 | 支持 20 并发写入不出现回执错乱 |
| 数据完整性 | 链下文件摘要与链上一致率 100% |
| 安全 | 密码 BCrypt 存储；接口 JWT 鉴权；私钥不入库、不进代码仓库 |
| 可复现 | 全新环境按部署手册可在 2 小时内跑通 |

## 八、验收演示脚本

1. **正常链路**：登记批次 → 录入种植 → 录入采收 → 提交质检（合格）→ 运输交接 → 上架销售 → 扫码查看 6 条记录与交易哈希。
2. **异常链路**：另取一个不合格批次 → 尝试上架被拦截（展示 revert 信息）→ 监管处置 → 由该批次追查上游生产主体与下游物流单号。
3. **可信验证**：现场修改一份链下报告文件 → 点击"校验" → 页面提示摘要不一致。
